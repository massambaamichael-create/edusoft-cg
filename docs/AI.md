# AI.md — EduSoft CG

## 1. Règle de gouvernance (non négociable)

L’IA **n’a pas d’autorité autonome** sur les données critiques.

Elle peut :
- proposer
- générer
- analyser
- détecter
- assister

Elle ne doit **pas** décider seule de :
- publier un examen officiel
- modifier une note définitive
- effectuer un remboursement
- modifier une écriture comptable
- signer un document officiel
- changer une permission
- supprimer une donnée historique

## 2. Capacités cibles

- Génération de sujets d’évaluation
- Génération de corrigés (réponses attendues, méthode, étapes, barème détaillé, erreurs fréquentes)
- Variantes A/B/C pédagogiquement équivalentes
- Analyse des résultats et des compétences
- Analyse de progression pédagogique
- Assistance aux utilisateurs (suggestions, détections d’anomalies)
- Aide à la décision (recommandations opérationnelles)

## 3. Contexte obligatoire

Toute génération de sujet doit s’appuyer sur les données pédagogiques d’EduSoft (programme, progression réelle, compétences, classe, matière).

Un sujet déconnecté du programme n’est pas acceptable.

## 4. Workflow de génération

Demande → Génération IA → Sujet + corrigé → Contrôle humain → Modification → Validation → Publication

Pour les examens importants : plusieurs niveaux de validation configurables (Enseignant → Directeur des Études → Directeur).

## 5. État actuel

Couche IA **absente**. Priorité : Release 8 (après stabilisation des modules pédagogiques et d’évaluation).
